# Бесплатный СВЧ-дайджест для Telegram

MVP автоматически раз в неделю собирает свежие материалы о СВЧ-технике и антеннах, удаляет повторы, ранжирует кандидатов, составляет русскоязычный выпуск через бесплатную квоту GitHub Models и публикует его в Telegram-канал.

## Почему MVP бесплатный

- источники: открытые RSS/Atom и arXiv API;
- запуск: GitHub Actions в публичном репозитории;
- редактура: бесплатная ограниченная квота GitHub Models через встроенный `GITHUB_TOKEN`;
- публикация: бесплатный Telegram Bot API;
- база уже использованных ссылок: JSON-файл в самом репозитории.

Платный X API в MVP не используется. Его можно добавить позже отдельным модулем.

## Что делает система

1. Загружает публикации за последние восемь дней.
2. Отбирает материалы по техническим ключевым словам.
3. Удаляет дубликаты по URL и похожим заголовкам.
4. Передаёт не более 28 лучших кандидатов редактору GitHub Models одним запросом.
5. Модель выбирает 3–10 материалов и пишет русский текст только по данным источника.
6. Код подставляет исходные URL самостоятельно, поэтому модель не может выдумать ссылку.
7. В режиме `publish` бот отправляет выпуск в Telegram и помечает материалы использованными.
8. Архив выпуска сохраняется в `output/`.

## Что должен сделать владелец канала

### 1. Создать канал и бота

1. Создайте публичный Telegram-канал и задайте ему username, например `@rf_weekly_ru`.
2. В диалоге с `@BotFather` выполните `/newbot` и сохраните полученный токен.
3. Добавьте бота администратором канала с правом публикации сообщений.

### 2. Создать публичный репозиторий GitHub

Загрузите в него содержимое этого проекта. Публичный репозиторий нужен, чтобы стандартные GitHub Actions не расходовали платные минуты.

### 3. Добавить две настройки

В репозитории откройте **Settings → Secrets and variables → Actions**.

- Вкладка **Secrets**: создайте `TELEGRAM_BOT_TOKEN` и вставьте токен бота.
- Вкладка **Variables**: создайте `TELEGRAM_CHANNEL` со значением вида `@rf_weekly_ru`.

Токен нельзя записывать в файлы проекта или сообщения.

### 4. Первый тест

Откройте **Actions → Weekly RF Digest → Run workflow**.

- `publish = false`: сформировать выпуск и сохранить его в `output/latest.md`, но не отправлять в Telegram.
- `publish = true`: сформировать и опубликовать выпуск.

После проверки расписание будет автоматически запускаться каждый понедельник в 08:00 по Красноярску.

## Настройка тематики

Все источники, ключевые слова и веса находятся в `config/sources.yml`. Чем выше вес, тем выше вероятность попадания материала в редакторский отбор.

Особенно высокие веса уже заданы для:

- антенн, ФАР, reflectarray и metasurface;
- облучателей, OMT и поляризаторов;
- волноводов и СВЧ-фильтров;
- ближнепольных измерений и NF–FF;
- Ka-, Ku- и E-диапазонов;
- спутниковой связи, радиолокации, MMIC и RFIC.

## Защита от галлюцинаций

- модель видит только заголовок, описание, дату и имя источника;
- модель возвращает ID выбранного материала, а не URL;
- URL берётся из исходной записи;
- численные данные запрещено добавлять, если их нет в описании;
- выпуск не публикуется, если модель вернула меньше минимального числа корректных материалов.

## Ограничения MVP

- RSS некоторых сайтов иногда меняет адрес или временно недоступен;
- бесплатная квота GitHub Models ограничена и предназначена для прототипов;
- X, LinkedIn и закрытые источники не включены;
- автоматическая публикация всё равно требует периодического человеческого просмотра качества.

## Локальный запуск

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\\Scripts\\activate
pip install -e ".[dev]"
pytest -q
rf-digest --mode preview
```

Для локального запуска задайте переменные из `.env.example`. Для GitHub Actions отдельный токен модели не нужен.
